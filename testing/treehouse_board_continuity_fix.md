# Board-game continuity corrections

## Observable failure

A complete original money game was recorded from the existing ordinary starting
snapshot, using mouse inputs only. The player wins with 56 cents; the robot has
39 cents. No original memory was modified. The capture is
`output/treehouse/board-native-completion-a` (24 inputs, 25 checkpoints).

The browser was initialized from that starting snapshot once and then given the
same mouse choices without resetting its state or random seed between turns.
The first 18 checkpoint states matched. At `step-17`, the robot reached the
same square but offered 10/12 cents instead of the original 8/9. Its random seed
differed, and subsequent board layouts and balances diverged.

Failing complete-game evidence:
`output/treehouse/board-native-completion-check-a/report.json`.
The minimized reproduction loads `step-16` and presses the visible roll button;
its failing trace is `output/treehouse/board-rng-diagnosis-a/report.json`.

## Cause and correction

Original overlay 3, `0308..0336`, draws a direction from all four directions and
retries when the adjacency entry is negative. The browser selected from a list
containing only existing roads. Both methods can reach the same square, but
they consume different portions of the shared random sequence.

On this turn, the road at node 21 permits only left. The original rejects eight
directions before drawing left. The corrected browser now makes those draws,
produces amounts 8/9 and ends at the original seed `2198293132`. This correction
applies to both game types and every goal; the final-step preference for the
best square is unchanged. Evidence: `board-rng-diagnosis-a/fixed.json`.

A separate short-sequence comparison also found that ordinary money credits
left `remaining` at zero. Original overlay 3 resets it to -1 on return to the
roll state (`20E3`). Money credit now performs that reset after its animation
and ending handling, matching chip transfers and winning money endings.
The old-build failure is retained in
`board-native-journey-baseline-b/report.json`.

## Verification scope

`board-native-completion-check-b/report.json` matches all 25 complete RGB
checkpoint images and every checked state/random-seed field through victory.
The short comparison also matches all seven checkpoints, including the native
hint and mid-delivery image. These are images actually generated by gameplay;
reference pixels are used only in the comparison tool.

Inputs occur after animation completion plus a fixed idle observation window.
This establishes continuous rules/state behavior and ordered image membership,
not equality at native input times, every intermediate redraw, audio waveforms,
fresh-boot random initialization or every possible route. Those remain tracked.

The earlier checks mainly initialized separate native snapshots. Continuous
whole-game comparisons expose sequence errors that those checks cannot catch.
The new complete-game verifier is now part of the regression suite. Diagnostic
instrumentation was confined to the browser probe; no debug wrapper was added
to the shipped game.
